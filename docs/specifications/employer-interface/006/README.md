# Employer Interface — Version 006

This directory contains the official Version 006 XSD schemas used by Alpha as the source of truth for Employer Interface XML validation.

## Official schemas

| Document type | Official file | Interface type |
| --- | --- | --- |
| Current / regular employer report | `mimshak_maasikim_shotef_xsd_schema_006.xsd.xml` | `SUG-MIMSHAK = 12` |
| Negative employer report | `mimshak_maasikim_shliliim_xsd_schema_006.xsd.xml` | `SUG-MIMSHAK = 13` |
| Summary feedback | `mimshak_maasikim_mesakem_xsd_schema_006.xsd.xml` | Summary feedback (`14` / `18` according to the schema) |
| Annual summary feedback | `mimshak_maasikim_mesakem_shnati_xsd_schema_006.xsd.xml` | `SUG-MIMSHAK = 16` |

All four files declare Employer Interface XML version `006` and are copied into the API runtime output during build/publish.

## Runtime behavior

Incoming XML is validated against all four official schemas. Exactly one schema must match before the document is accepted. Current and negative documents are routed to report import; summary and annual-summary documents are routed to feedback ingestion.

Outgoing XML is report-type-aware:

- `ManualReportKind.Current` is built with the dedicated current-report Version 006 builder and must validate against the current-report XSD.
- `ManualReportKind.Negative` is built with the dedicated negative-report Version 006 builder and must validate against the negative-report XSD.
- Difference reports are not transmitted directly; they must first be materialized as a current or negative report.
- Summary and annual-summary documents are feedback documents and are ingestion-only in the current Alpha flow.

The current and negative schemas are not treated as the same XML with only a different `SUG-MIMSHAK`. They have different required/optional fields and different allowed values. For example, negative reports allow `SUG-PEULA` values `5` or `6`, while current reports use the current-report operation-code set.

Before transmission, Alpha validates the generated bytes against the matching official XSD. Only the exact byte array that passed validation is hashed and passed to the transmission provider.

## Required application data

Version 006 requires data that is not optional at the business/API level even when older Alpha screens did not collect it. Alpha therefore stores dedicated Employer Interface profile/metadata fields and fails closed when mandatory data is missing instead of inserting placeholder values.

This includes employer contact information, employee Version 006 profile information for current reports, report-product interface metadata, payment/bank fields, and the externally configured recipient identity under `EmployerInterface006` settings.

## Testing

`tests/Alpha.Api.Tests/EmployerInterface006XmlBuilderTests.cs` builds representative current and negative XML documents and validates them against these exact official XSD files. The tests run in CI.

## Rule

Do not modify or relax these XSD files to make application output pass validation. The application code and data model must conform to the official schemas, not the other way around.
